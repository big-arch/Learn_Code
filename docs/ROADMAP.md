# Обновление Python Studio

Реализовано: 24 урока базового Python с теорией, вопросами, настоящим выполнением кода, финальным проектом; 3D-обсерватория и lofi. Следующие шаги: расширить курс практическими проектами и повторением, затем перенести структуру на JavaScript и C#. Для общего сервиса — Supabase Auth + PostgreSQL/RLS и межустройственное сохранение.

Ниже сохранены идеи первой версии; пункты про полный базовый Python теперь реализованы.

# Варианты развития

## Рекомендуемый путь

Сначала проверить вводный маршрут на 5–10 людях, которые не писали код. Попросить их пройти первый урок без объяснений автора. Измерить: понял ли человек команду, смог ли исправить ошибку, может ли написать похожую команду без копирования.

Не обещать «освоенный язык» за прохождение двух задач. Следующий этап — перенос навыка в маленький реальный проект.

## Три варианта хранения

| Вариант | Для чего | Что уже есть / потребуется |
| --- | --- | --- |
| SQLite + Node.js | Локальный запуск, демонстрация, личное обучение | Реализовано: таблица прогресса, миграция, API, отдельные ключи профилей, резерв в браузере |
| Supabase + PostgreSQL | Публичный сайт, аккаунты, обучение с разных устройств | Рекомендуемый следующий этап: Auth, RLS по auth.uid(), таблицы profiles/completions/drafts, серверная проверка |
| PostgreSQL + свой API в Docker | Собственная инфраструктура и полный контроль | Понадобятся аккаунты, обновления, резервирование, HTTPS и эксплуатация сервера |

Supabase предоставляет полноценную PostgreSQL-базу, а не отдельный язык базы данных. Документация: https://supabase.com/docs/guides/database/overview и https://supabase.com/docs/guides/database/postgres/row-level-security.
Облачный проект не создан, платные ресурсы не заказаны, учётные данные не требуются для локального запуска.

## Приоритетные идеи

1. **Один сильный путь вместо множества коротких демо.** Расширить Python или JavaScript до 15–20 уроков: значения → переменные → условия → циклы → функции → маленький проект.
2. **Предскажи результат.** До запуска спросить, где окажется робот. После запуска сравнить прогноз и результат.
3. **Отладка как игра.** Готовая сломанная программа; нужно найти одну ошибку, затем объяснить исправление.
4. **Переменные как ячейки памяти.** Визуальные контейнеры значений; изменение переменной сразу видно в сцене.
5. **Мост в реальный код.** После симулятора — маленький JavaScript-проект в изолированном Web Worker с лимитом времени. Для Python — отдельный Pyodide-worker. Go/C# требуют изолированного сервиса компиляции; не запускать ученический код в процессе API.
6. **Наставник без готового ответа.** Сначала уточняющий вопрос, затем подсказка по конкретной ошибке, решение — только по отдельному запросу.
7. **Проекты по интересам.** Свой сайт, мини-игра, автоматизация файлов, анализ таблиц. Для вас можно сделать отдельный маршрут к Python/Revit и C#.
8. **Аккаунт Supabase.** Сохранение между устройствами, история решений, экспорт личных данных; рейтинги только после серверной проверки XP.

## Дизайн

Сохранить тёмный исследовательский мир и лаймовый акцент. Строить каждый урок вокруг одного действия, показывать результат рядом с редактором, оставлять объяснение сворачиваемым. 3D должно объяснять выполнение программы. Все сценарии обязаны работать без WebGL и без анимации.
