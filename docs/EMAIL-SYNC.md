# Вход по email и перенос прогресса

Адрес сайта: https://big-arch.github.io/Learn_Code/

1. Нажать **Войти**, ввести почту и открыть ссылку из письма.
2. В **Аккаунте** нажать **Перенести гостевой прогресс**, если до входа уже проходили задания в этом браузере.
3. На другом устройстве запросить письмо на тот же адрес. Прогресс загрузится после входа.

Переносятся завершённые уроки, задания, XP (без повторного начисления), черновики основного курса, Арены, острова, мастерской и дополнительных видеопрактик, настройки звука и движения. Введённые временные input()-данные и открытая вкладка урока не синхронизируются.

Гостевой профиль отдельный. Он не перезаписывается аккаунтом при выходе и не импортируется в другой аккаунт автоматически. Перенос из гостя относится к текущему браузеру и адресу сайта: localhost и GitHub Pages имеют разные браузерные хранилища.

## Синхронизация

Изменения отправляются через 650 мс после редактирования. Восстановление сети, возвращение на вкладку и периодическая проверка раз в 30 секунд подтягивают облачные изменения. Кнопка «Синхронизировать» запускает проверку вручную. Офлайн-изменения хранятся под отдельным ключом аккаунта и повторно отправляются после восстановления связи.

Объединение выполняется относительно предыдущей синхронизированной версии. Достижения объединяются; XP пересчитывается по известным заданиям. Независимые черновики сохраняются вместе. При изменении одного черновика с двух устройств обе версии показываются в аккаунте для явного выбора. Во время незавершённого запроса новые локальные правки не теряются.

Сброс требует доступного облака. Он увеличивает поколение состояния: старая офлайн-копия не возвращает удалённые достижения. Предыдущая локальная копия остаётся доступна для скачивания в аккаунте.

## Подключение

По выбору владельца использован существующий проект **big-arch's Project**, ref `renbakjudvdnkjvjujti`. Созданы только объекты с префиксом `learn_code_`: таблица `learn_code_progress`, проверка состояния и RPC `learn_code_sync`. Схема — `server/learn-code-cloud.sql`, применена миграция `learn_code_email_progress`.

Вход — Supabase Auth Magic Link, клиентская SPA использует официальный SDK 2.119.0 и поддерживаемый implicit callback. Токены в URL обрабатывает SDK; приложение не пишет их в логи. Секретные/service-role ключи не используются. Публичный URL проекта и publishable key задаются переменными сборки `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`; они доступны клиенту по назначению.

RLS ограничивает SELECT/INSERT/UPDATE условием `auth.uid() = user_id`. RPC работает как SECURITY INVOKER, требует вход и сам определяет user_id. Анонимный доступ к таблице и RPC отозван. Проверка revision и блокировка строки предотвращают потерю состояния при одновременной записи. Письма и Redirect URLs настраиваются в Supabase; владелец подтвердил настроенный SMTP и добавление адреса сайта в Redirect URLs.

Для локальной облачной сборки заполнить `.env.local` по `.env.example`; без переменных аккаунты скрыты, гостевой/SQLite режим работает как раньше. Для тестирования email-входа в локальную версию дополнительно требуется подходящий адрес возврата; опубликованная форма направляет письмо на рабочий сайт.

## Проверки

- `npm run test:cloud`: 8 сценариев двух устройств, конфликтов, импорта гостя, перезапуска офлайн, изоляции кэша, сброса и изменений во время отправки.
- `qa/account-checks.mjs`: 10 UI-проверок в двух изолированных браузерных контекстах с имитацией auth/RPC: обновление открытого редактора, конфликт, выбор версии, выход, перенос гостя, форма email и мобильная вёрстка. Письма этим тестом не отправляются.
- Реальный PostgreSQL: в транзакции с откатом проверены CAS, поколение сброса и отсутствие чтения/изменения чужой строки. Временные пользователи не сохранены.
- Проверка Supabase advisors не показала замечаний к созданным объектам. Настройки и таблицы других приложений не изменялись.
- Регрессия мастерской: 55 браузерных проверок всех 16 уровней, в том числе мобильных.

Тесты с имитацией входа не заменяют проверку доставки письма. Её результат фиксируется отдельно при публикации.

Официальные источники: [email Magic Link](https://supabase.com/docs/guides/auth/auth-email-passwordless), [почтовый сервис](https://supabase.com/docs/guides/auth/auth-smtp), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).
